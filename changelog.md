## [0.2.4] - 2026-08-16

Fork of the original `jackhumbert/cyberpunk2077-input-loader` (v0.2.3). Same
purpose — merge `r6/input/*.xml` files into the game's `inputContexts.xml`
and `inputUserMappings.xml` cache files at startup — with a thorough pass of
bug fixes, defensive hardening, and a new audit-trail logging system for
diagnosing mod-induced crashes.

This is the first release of `Artheriax/cyberpunk2077-input-loader-fork`. All
changes below are relative to upstream v0.2.3.

### Added

#### Crash forensics — audit trail logging

Every game launch now produces a detailed audit log at
`red4ext/logs/input_loader.log` showing exactly what each mod did:

- **Per-node audit lines** for every merge operation, marking whether each
  node was added (`+`), replaced (`~`), or appended (`+ appended N children`)
  with the mod filename and the affected node's `name` attribute.
- **Per-mod summary line** at the end of each mod's processing, showing the
  total added / replaced / appended / skipped counts for that file.
- **Final summary block** at the end of `LoadInputConfigs` with totals for
  mods processed, mods skipped, nodes added/replaced/appended/skipped, and
  errors. Warnings are emitted when nodes were replaced or errors occurred,
  pointing the user at the relevant log lines above.
- **Cache-file provenance comment** — the generated `r6/cache/inputContexts.xml`
  and `r6/cache/inputUserMappings.xml` files now start with an XML comment
  showing the input_loader version, the generation timestamp, the merge
  statistics, and a "do not edit by hand" notice. Users debugging crashes can
  tell at a glance whether a cache file was generated by input_loader or is
  a vanilla game file.
- **`SaveDocumentWithAudit` helper** — replaces the previous direct
  `save_file()` calls with a `std::ofstream`-based approach that prepends
  the provenance comment, then calls `doc.save(stream)`. Uses
  `std::strerror(errno)` on file-open failures so users get real
  "Permission denied" / "Disk full" messages instead of just "Failed to save".

#### Defensive null / state checks

- `Add()` now null-checks its `str` parameter and logs an error instead of
  dereferencing nullptr when a misbehaving RED4ext plugin calls
  `InputLoader::Add(handle, nullptr)`.
- `Add()` now uses the wide-character `GetModuleFileNameW` API with dynamic
  buffer resizing, replacing the previous fixed 512-byte ANSI buffer that
  would truncate or overflow on DLL paths longer than 511 characters.
- `MergeDocument` now validates the `LoadDocument` status flag and bails out
  with a clear error if the mod XML failed to parse, instead of silently
  proceeding with an empty document and producing a partial merge.
- `MergeDocument` now explicitly fetches and validates the `<bindings>` root
  node of both the mod document and the target document before iterating,
  with a clear warning if the root is missing.
- `FileStream::ReadWrite`, `GetPointerPosition`, and `Seek` now check
  `IsOpen()` before performing any operation, with a warning logged if the
  file is not open. Previously they would call Win32 APIs on
  `INVALID_HANDLE_VALUE`.
- `FileStream::Flush` now actually calls `FlushFileBuffers` instead of
  unconditionally returning `true`.

#### Build / packaging infrastructure

- **`build.bat`** — one-shot build script that verifies MSVC and Ninja are
  on PATH, initializes git submodules if missing, configures CMake with the
  right generator / compiler / policy overrides, builds the DLL, and
  installs into `game_dir/`. Removes the need to remember long CMake
  command-line invocations.
- **`package.bat`** — produces the two distribution zips
  (`input_loader_vX.X.X.zip` and `input_loader_vX.X.X_pdb.zip`) in a
  `dist/` folder, with the exact Cyberpunk 2077 install-tree layout
  expected by Vortex and manual installers. Version is auto-detected from
  `CMakeLists.txt`.
- **`tools/install.bat`** — rewritten to validate the build output exists
  and that the target game directory actually contains
  `bin/x64/Cyberpunk2077.exe` before copying. Accepts an optional
  custom game-path argument.
- **`.vscode/tasks.json`** — VS Code tasks wrapping `build.bat`,
  `package.bat`, and `tools/install.bat`.
- **`.github/workflows/build.yaml`** — single clean GitHub Actions workflow
  replacing the previous broken `build.yaml` + `release.yaml` pair.
  Uses `actions/checkout@v4`, `ilammy/msvc-dev-cmd@v1`, and
  `seanmiddleditch/gha-setup-ninja@v6`. Produces release artifacts and
  creates a GitHub Release when a `v*` tag is pushed.
- **README** — rewritten with quick-start build instructions, a crash
  debugging section explaining the new audit log, and a clearer uninstall
  procedure.

### Changed

#### Public API behavior (backward-compatible)

The public `InputLoader::Add(PluginHandle, const wchar_t*)` signature is
**unchanged** — existing RED4ext plugins that call it do not need to be
recompiled. Behavior changes:

- `Add()` is now **thread-safe**. Concurrent calls from different RED4ext
  plugins are serialized via a `std::mutex` protecting the internal
  `document_paths` vector. Previously the call had a data race that could
  lead to heap corruption and game crashes when multiple plugins registered
  inputs at the same time.
- `LoadInputConfigs` now **snapshots** the `document_paths` vector under
  the mutex before iterating, so a late `Add()` call during the merge phase
  no longer causes iterator invalidation / UB.

#### Logging

- `LoadInputConfigs` now logs the `ex.what()` message from caught exceptions
  (previously the line was commented out, so only the file path was logged
  with no exception detail).
- `MergeDocument` logs each mod node's `name` attribute alongside its node
  type, so users can identify *which* input was modified, not just *that*
  one was.
- Log messages use the corrected spelling "occurred" instead of "occured".
- `CreateLogger` now reports whether the file sink was successfully created
  or whether the logger is console-only.

#### File handling

- `LoadInputConfigs` now creates the `r6/cache/` directory before calling
  `save_file()`. Previously, if the cache directory was missing (fresh
  install, antivirus cleanup, etc.), `save_file` would silently fail and
  the game would launch with no input config at all → broken controls,
  unplayable.
- `save_file()` return values are now checked. Failures are logged with
  the target path.
- `recursive_directory_iterator` in `LoadInputConfigs` now filters to
  regular files only via `is_regular_file(ec)`. Previously, directories,
  symlinks, and socket entries could be passed to `MergeDocument`, causing
  parse failures or, in the case of symlink loops, an infinite recursion
  that would hang the game on launch.
- `.xml` extension matching is now **case-insensitive**. NTFS preserves
  file case, so a stray `.XML` mod file would previously be silently
  skipped. Now `.xml`, `.XML`, `.Xml`, etc. are all matched.

#### `LoadOriginals`

- `LoadOriginals` now checks the parse status of `r6/config/inputContexts.xml`
  and logs an error if it failed. Previously only `inputUserMappings.xml`
  had a fallback path (loading the bundled backup); `inputContexts.xml`
  had no fallback and would silently produce a partial merge if the
  upstream file failed to parse.
- `inputUserMappings.xml` fallback logic uses clearer variable names
  (`mappingsOk` instead of `fixed`).

#### `Utils`

- `CreateLogger` now builds a **console-only `spdlog::logger` first** and
  registers it as the default, then attempts to add the file sink inside
  try/catch. If the file sink fails (permission denied, missing directory,
  etc.), the logger falls back to console-only mode instead of throwing
  an exception out of `DllMain` (which would cause Windows to refuse to
  load the DLL entirely).
- `CreateLogger` also creates the `red4ext/logs/` directory if it doesn't
  exist, wrapped in try/catch. Failures go to `OutputDebugStringA` since
  the logger isn't constructed yet.
- `GetRootDir` no longer uses the unbounded `do { ... } while
  (GetLastError() == ERROR_INSUFFICIENT_BUFFER)` pattern. `GetModuleFileName`
  does not clear the last error on success, so a stale
  `ERROR_INSUFFICIENT_BUFFER` from a previous iteration could persist and
  loop forever. Now uses a bounded `for` loop (max 16 iterations) that
  resets the last error before each call and drives the loop using the
  return value (`length < bufferSize-1` means success) plus a fresh
  last-error check.
- `GetRootDir` now captures the error code immediately on failure and
  emits it to `OutputDebugStringA` (formatted via `_ultoa` in hex).
- `ToWString` now uses **two-pass `MultiByteToWideChar`** (first call
  queries the required length, second call does the conversion) instead
  of the previous `std::wstring(L"", length)` pattern which was undefined
  behavior for `length > 1` (it copies `length` characters from a
  1-character string literal, reading past the end). The new approach
  also trims embedded NULs in fallback paths and properly resizes the
  result to the actual converted length.
- `ToWString` now null-checks its input and returns an empty wstring
  instead of calling `strlen(nullptr)`.

#### Build system

- `cmake_minimum_required` bumped from `3.4` to `3.5...3.31`. CMake 4.x
  removed support for `cmake_minimum_required` versions below 3.5, which
  broke fresh clones on modern CMake. The `3.5...3.31` range form
  explicitly tells CMake the project is tested through 3.31.
- `project()` now specifies `LANGUAGES CXX` explicitly (was inferred).
- Submodule URLs in `.gitmodules` switched from SSH (`git@github.com:...`)
  to HTTPS so that fresh clones work without requiring an SSH key.
- The unused `detours` submodule has been removed entirely (it was
  commented out in `CMakeLists.txt` but still in `.gitmodules`).
- `build.bat` passes `-DCMAKE_POLICY_VERSION_MINIMUM=3.5` so submodules
  that still declare `cmake_minimum_required(VERSION 3.4)` (spdlog,
  pugixml) compile without manual patching.
- `build.bat` passes `-DCMAKE_C_COMPILER=cl -DCMAKE_CXX_COMPILER=cl`
  explicitly so CMake picks MSVC even if Clang is ahead of MSVC on `PATH`.
- `CMakeLists.txt` sets `CMAKE_POLICY_DEFAULT_CMP0175` to `OLD` because
  the `cyberpunk_cmake` submodule uses the deprecated
  `add_custom_command(TARGET ... DEPENDS ...)` form which CMake 3.28+
  rejects via policy CMP0175.

#### `stdafx.hpp`

- Added `<algorithm>`, `<cerrno>`, `<cstring>`, `<mutex>`, `<string>`
  includes that were being pulled in transitively. `<iostream>` (unused)
  removed from `Main.cpp`.

#### `DllMain`

- Now returns `TRUE` (the Win32 BOOL value) instead of `true` (the C++
  boolean literal). Both are 1 in practice, but the Win32 type is `BOOL`.

### Fixed

- **Data race in `Add()`** that could corrupt the `document_paths` vector
  when multiple RED4ext plugins called `Add()` concurrently — caused
  intermittent crashes on launch in larger modpacks.
- **Iterator invalidation in `LoadInputConfigs`** when a late `Add()` call
  mutated `document_paths` during iteration.
- **UB in `ToWString`** for `length > 1` inputs — read past end of
  string literal.
- **Infinite loop in `GetRootDir`** if `GetModuleFileName` left a stale
  `ERROR_INSUFFICIENT_BUFFER` in the last error.
- **Exception in `DllMain`** when `red4ext/logs/` directory didn't exist —
  caused the entire DLL to fail to load, which RED4ext reported as
  "input_loader.dll failed to load" with no further detail.
- **Silent cache write failure** when `r6/cache/` directory didn't exist —
  game launched with no input config, controls broken, no log entry
  indicating why.
- **Silent skip of `.XML` files** in `r6/input/` due to case-sensitive
  extension comparison.
- **Potential hang on launch** if `r6/input/` contained a symlink loop.
- **ANSI path truncation in `Add()`** for DLL paths longer than 511
  characters — could happen with deeply nested plugin install paths.
- **Missing `<bindings>` root in mod XML** silently produced a partial
  merge with no warning. Now logged.
- **Missing `<bindings>` root in target document** caused `child("bindings")`
  to return an empty node, and subsequent `remove_child` / `append_copy`
  calls operated on nothing — silently lost the mod's data. Now the
  `<bindings>` root is recreated if missing, with a warning.
- **`FileStream::Flush` was a no-op** — returned `true` without actually
  flushing the underlying file buffer. Now calls `FlushFileBuffers`.
- **`FileStream` operations on closed handles** would invoke Win32 APIs
  on `INVALID_HANDLE_VALUE`, with undefined behavior. Now guarded by
  `IsOpen()` checks.

### Removed

- The `detours` submodule and `cmake/FindDetours.cmake` — Detours was
  commented out in `CMakeLists.txt` and never actually used.
- `compile_commands.json` from the repo root — it was a build artifact
  committed by mistake.
- `.vscode/cmake-kits.json` — contained a hard-coded user-specific path
  (`C:/Users/Jack/...`) that didn't apply to anyone else.
- The separate `.github/workflows/release.yaml` — merged into
  `build.yaml` to simplify the CI setup.
- The unused `#include <iostream>` in `Main.cpp`.
